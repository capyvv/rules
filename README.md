# capyvv/rules

个人 Clash / Mihomo 规则配置。

## 设计原则

本项目基于 ACL4SSR 公共规则，仅维护个人策略，不重复维护大量公共规则。

核心原则：

1. **精确规则优先于宽泛规则**
   - 业务专用规则（AI、Google、媒体、开发工具等）优先匹配。
   - 宽泛规则（ProxyGFWlist、ChinaDomain、GEOIP）放在后面作为兜底。
   - Clash/Mihomo 规则按照从上到下顺序匹配，命中后停止继续匹配。

2. **节点选择与业务分流分离**
   - `🚀 节点选择` 仅作为基础出口选择器，不直接承载网站规则。
   - `♻️ 自动选择` 使用测速机制选择延迟较低节点。
   - 各业务分组引用节点选择或自动选择，方便单独调整出口。

3. **隐藏强制直连规则**
   - 局域网地址、公司内网域名、明确白名单直接使用 `DIRECT`。
   - 不创建额外策略组，避免用户误操作。

4. **专用服务独立分组**

   - AI 服务
     - OpenAI
     - Claude
     - Gemini

   - Google 服务
     - Google
     - Google FCM
     - GoogleCN

   - 开发工具
     - GitHub 等开发相关服务

   - 媒体服务
     - 国内媒体
     - YouTube / Netflix 等海外媒体

5. **普通海外服务统一处理**

   - 使用 ACL4SSR 的 `ProxyGFWlist.list`。
   - 不单独维护大量海外网站列表。
   - 统一进入海外服务策略组。

6. **国内直连作为后置兜底**

   顺序：

   ```text
   专用服务规则
       ↓
   普通海外代理规则
       ↓
   ChinaDomain
       ↓
   ChinaCompanyIp
       ↓
   GEOIP,CN
       ↓
   FINAL
   ```

   避免宽泛国内规则覆盖前面的精确业务规则。

## 自动选择说明

`♻️ 自动选择` 使用 Mihomo 的 `url-test` 策略：

- 定期访问测速地址；
- 测量节点响应时间；
- 自动选择延迟较低的节点。

当前节点规模较小（美国、新加坡节点），统一测速即可，无需拆分地区测速组。

## 规则维护原则

- 优先引用 ACL4SSR 等成熟公共规则。
- 仅针对实际遇到的问题增加自定义规则。
- 避免重复维护已有公共列表。
- 新增规则前先确认是否会与已有规则产生优先级冲突。

## 当前规则结构

```text
DIRECT 隐藏规则
    ↓
广告拦截
    ↓
AI / Google / Microsoft / Apple / GitHub / 媒体等专用服务
    ↓
国内媒体
    ↓
普通海外服务 ProxyGFWlist
    ↓
国内直连兜底
    ↓
漏网之鱼 FINAL
```
